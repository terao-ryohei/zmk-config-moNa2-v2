## Project Overview

This is a ZMK firmware configuration for the moNa2 split keyboard with the following features:
- Split keyboard design (left/right halves)
- Based on Seeeduino XIAO BLE microcontroller
- PMW3610 trackball sensor on the right half with auto-mouse (temp-layer) and scroll mode support
- Rotary encoder on the left half
- RGB LED support via rgbled_adapter
- ZMK Studio / DYA Studio support for live configuration
- 40-key layout with 7 layers (default, numbers/symbols, special chars, navigation/media, system, mouse, scroll)

Based on upstream `sayu-hub/zmk-config-moNa2-v2` branch `feature/dya-studio-support` (ZMK `main+dya` fork by cormoran, Zephyr 4.1).
Only the keymap and the items listed under "Local deltas from upstream" differ from upstream.

## Building Firmware

The firmware is built automatically via GitHub Actions on push/PR. The build configuration is defined in `build.yaml`.

**Build targets** (board `xiao_ble/nrf52840/zmk`):
- `mona2_r-pmw3610` - Right half with PMW3610 trackball and Studio (`studio-rpc-usb-uart` snippet). Use this one
- `mona2_r-paw3222` - Right half for PAW3222 sensor (not used on this unit)
- `mona2_l` - Left half with encoder
- `settings_reset` - Settings reset shield

Build artifacts (.uf2 files) are generated by GitHub Actions and can be flashed to the keyboard.

## Repository Structure

**Hardware Definition:**
- `boards/shields/mona2/` - ZMK shield definition for moNa2 keyboard
  - `mona2.dtsi` - Matrix transform, kscan, physical layout, trackball listener stub, encoder
  - `mona2_l.overlay` - Left half GPIO configuration (encoder on xiao_d 0/5)
  - `mona2_r.overlay` - Right half: PMW3610 via SPI (CS=P0.09, SCLK=P0.05, SDIO=P0.04, MOTION=P0.02), runtime input processors (mouse / scroll / temp-layer), mouse gesture, inertial scroll
  - `Kconfig.shield` / `Kconfig.defconfig` - Kconfig shield definitions

**Keymap Configuration:**
- `config/mona2.keymap` - Main keymap file with layer definitions, combos, macros, and behaviors
- `config/mona2_r.conf` - Right half config (PMW3610 axis, RGB LED, Studio / DYA modules, Bluetooth, encoder, battery)
- `config/mona2_l.conf` - Left half config (encoder, battery, diagnostics)

**Dependencies:**
- `config/west.yml` - West manifest. ZMK is cormoran `main+dya`; most DYA modules track `main` (not pinned), so a rebuild can pick up upstream changes

## Hardware-Specific Notes

**COROPIT Trackball Configuration:**

Axis inversion is set by Kconfig in `config/mona2_r.conf` (`CONFIG_PMW3610_INVERT_X/Y`), not in the overlay.
It can also be changed at runtime from DYA Studio.

**Trackball Features:**
- All layers: cursor movement via `&mouse_runtime_input_processor`
- Auto-mouse: moving the ball activates layer 5 (MOUSE: J/K/L = left/right/middle click) via the temp-layer of `&mouse_runtime_input_processor`. Delays are adjustable in DYA Studio
- Layer 3 (hold Space): scroll mode via `&scroll_runtime_input_processor` (`active-layers = 0x08`)
- CPI 600 in overlay (adjustable in DYA Studio)

**Key Configuration Details:**
- Matrix: 4 rows × 11 columns (col2row diode direction)
- Default combos: positions 39+38 = layer 4 + ESC, positions 11+12 = TAB
- Behavior modifications: `&mt` (balanced, quick-tap-ms=0), `&lt` (balanced, quick-tap-ms=300)
- Custom behaviors: `lt_to_layer_0`, `scroll_up_down`, `scroll_right_left`
- Encoder: steps 24, triggers-per-rotation 4
- Single base layer (0). `CONFIG_ZMK_DEFAULT_LAYER_MAX_INDEX=0` so OS detection never switches the base to layer 1

## Local deltas from upstream

- `config/mona2.keymap` - own keymap
- `boards/shields/mona2/mona2.dtsi` - left encoder enabled, steps 24, triggers-per-rotation 4
- `boards/shields/mona2/mona2_r.overlay` - scroll layer = 3, temp-layer (auto-mouse) to layer 5
- `config/mona2_r.conf` - PMW3610 axis inversion for COROPIT, default-layer range 0..0

## Development Workflow

1. Edit keymap in `config/mona2.keymap`
2. Modify board-specific settings in `config/mona2_r.conf` or `config/mona2_l.conf`
3. Hardware changes require editing `.overlay` and `.dtsi` files in `boards/shields/mona2/`
4. Push to trigger GitHub Actions build via `.github/workflows/build.yml`
5. Download .uf2 files from Actions artifacts and flash to keyboard
